# Кейс: ИИ-ассистент режиссёра

Альтаир x «Школа 21». Партнёр: Новосибирский государственный театральный институт
(Богданова Виктория Борисовна, Храновский Александр Юрьевич).

Постановка задачи — `TZ_director_assistant.pdf`. Это первоисточник.

Сбор художественных текстов — работа команд. В этом репозитории нет готового разобранного
проекта, нет весов и нет выгрузки пьес, на которой кто-то уже решил задачу.

## Что здесь лежит

| Файл | Зачем |
|---|---|
| `TZ_director_assistant.pdf` | ТЗ партнёра |
| `sources/open_texts.md` | где брать пьесы с открытой лицензией и чего избегать |
| `questions.md` | вопросы, без которых прототип превращается в чат-бота |
| `criteria.md` | минимум и сильный результат |
| `tests/test_no_solution_artifacts.py` | проверка, что сюда не положили готовый ответ |

## Задача коротко

Режиссёр загружает пьесу и должен получить не пустой чат, а проект: сцены, персонажи,
карточки с цитатами, хотя бы один вариант сценического решения, диалог, который помнит
правки. Обычного ChatGPT мало: путает события, выдумывает ремарки, не хранит постановку.

ТЗ прямо просит **компактную** модель и исследование, а не «подключить самую мощную
и скормить всё произведение».

## С чего начать

1. Прочитать ТЗ целиком. Отдельно — блоки про ограничения вычислительных ресурсов и про то,
   почему универсальный чат не подходит.
2. Поговорить с партнёром (кастдев): что он правит руками, какие ошибки ИИ для него
   неприемлемы, литературный vs пластический театр.
3. Взять 1–2 пьесы из общественного достояния. Указатели — `sources/open_texts.md`.
4. Сначала научиться **резать текст и цитировать**, потом генерировать мизансцену.
   Если генератор красиво описывает выход персонажа, которого в явлении нет, — это провал,
   а не креатив.

## Чего сюда не класть

Разобранный JSON проекта, `metadata.csv` готового корпуса, обученные веса, полный текст
пьесы «как у наставника получилось», скрипт, который один в один воспроизводит чужой датасет.
Команды собирают материал сами.
