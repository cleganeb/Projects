# Кейс: ИИ-композитор

Альтаир x «Школа 21». Партнёр — Новосибирский областной колледж культуры и искусств.
Постановка — `ТЗ_кейса_ИИ_композитор.docx` (первоисточник; если README и ТЗ расходятся, верьте ТЗ).

Короткий MIDI-мотив → несколько продолжений → сравнение. За четыре дня не учат большую
генеративную модель с нуля: гипотеза, свой корпус, адаптация, сравнение, интерпретация.

Сбор данных и самой базовой модели — работа команд. Готового чекпоинта и готового
корпуса здесь нет.

## Что нужно сделать

По ТЗ:

- собрать **базовый** MIDI-корпус и получить на нём рабочую генерацию;
- сформулировать музыкальную гипотезу (эпоха, фактура, жанр — свой выбор);
- собрать небольшой **дополнительный** корпус под эту гипотезу, с понятной лицензией;
- адаптировать модель (fine-tune или другой доступный способ);
- прогнать **те же** тестовые мотивы до и после;
- сравнить технически и на слух с музыкальным экспертом;
- показать сценарий: мотив → несколько продолжений → MIDI.

Исследовательский вопрос: как состав дополнительного датасета влияет на продолжение темы?

## Что где лежит

| Папка / файл | Зачем |
|---|---|
| `ТЗ_кейса_ИИ_композитор.docx` | постановка партнёра |
| `data/motifs/` | три **входных** мотива для сравнения «до / после». Это не обучающая выборка |
| `SOURCES.md` | куда смотреть за открытыми MIDI (база и доп. корпус) |
| `src/catalog.py` | фильтр лицензий и split по пьесе, не по такту |
| `src/metrics.py` | плотность, диапазон, интервал, повтор темы — по хвосту после мотива |
| `tools/compare.py` | сравнить два MIDI на одном мотиве |
| `tools/download_maestro.py` | индекс CSV из локального MAESTRO zip, без выбора «каких пьес хватит» |

Имена файлов латиницей. CSV — UTF-8 с BOM.

## Тестовые мотивы

`data/motifs/motif_leap.mid`, `motif_scale.mid`, `motif_stepwise.mid` — короткие одноголосные
фрагменты. На защите удобно показать **один и тот же** вход для базовой и дообученной модели.
Их не использовать как единственный train.

## Куда брать MIDI

Точки старта — `SOURCES.md`. Коротко:

- базовый корпус можно собрать из PD (хоралы music21, Mutopia, KernScores);
- MAESTRO MIDI-only (~58 МБ) — CC BY-NC-SA 4.0, для некоммерческого хакатона обычно ок, NC/SA наследуют производные;
- Lakh: каталог CC-BY 4.0, сами файлы часто с неясным © — не класть «пачкой».

Не коммитьте архивы на десятки мегабайт.

## Чего здесь нарочно нет

- обученного чекпоинта;

Собрать это — работа команды за 4 дня.

## Вопросы, которые стоит закрыть самим

Подсказки, не ответы.

1. Если в «базу» смешать несколько эпох «для объёма», как доказать, что сдвиг после дообучения дал доп. корпус, а не каша в базе?
2. Split по файлу vs по произведению: что будет, если нарезать один MIDI и часть тактов уедет в test?
3. Транспозиция увеличивает выборку. Когда она ломает гипотезу про тональность или тесситуру?
4. Доп. корпус из 8–12 пьес и 100 эпох: как отличить «выучила жанр» от «запомнила шесть мелодий»?
5. MAESTRO — NC-SA. Можно ли выложить дообученный чекпоинт в открытый git?
6. MIDI без лицензии в карточке: класть, выкидывать, как это закрепить в коде?
7. `notes_per_16` и `pitch_range` не слышат каденцию. Как показать эксперту, что тема сохранилась?
8. Если модель одноголосная, гипотеза «появится фактура ноктюрна (левая рука)» ею проверяется или нет?

## Как будут оценивать (из ТЗ)

**Техническая.** Открывается MIDI, не пустой файл, тот же входной мотив, измеримые изменения ритма / диапазона / плотности / повтора темы — до и после, на одном наборе мотивов.

**Музыкальная.** Сохранение темы, связность, выразительность — вместе с музыкальным экспертом, не одной колонкой CSV.

## Ограничение из ТЗ

Не учить большую генеративную модель с нуля за четыре дня. Вклад — гипотеза, корпуса, адаптация, сравнение.
